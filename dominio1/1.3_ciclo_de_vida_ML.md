# 🧩 AWS Certified AI Practitioner — Tarefa 1.3

## Descrever o ciclo de vida do desenvolvimento de ML

<p align="justify">A Tarefa 1.3 trata de como um modelo de Machine Learning passa por todo o seu ciclo de vida: desde os dados e experimentação até treinamento, avaliação, implantação, monitoramento e eventual retreinamento.</p>

<pre>
DADOS
  ↓
EDA
  ↓
PRÉ-PROCESSAMENTO
  ↓
FEATURE ENGINEERING
  ↓
TREINAMENTO
  ↓
AJUSTE DE HIPERPARÂMETROS
  ↓
AVALIAÇÃO
  ↓
DEPLOYMENT
  ↓
MONITORAMENTO
  ↓
RETREINAMENTO
  ↺
</pre>

> 🔥 **DECORA:** modelo treinado não significa modelo pronto para produção. O ciclo continua com deployment, monitoramento e, quando necessário, retreinamento.

---

<h3><strong style='color: skyblue'>1️⃣ Componentes de um pipeline de IA/ML</strong></h3>

### 📥 Coleta de dados

<p align="justify">É a obtenção dos dados necessários para desenvolver, treinar e avaliar o modelo.</p>

Exemplos:

- dados de clientes;
- transações;
- imagens;
- textos;
- sensores;
- histórico de vendas.

> **DECORA:** dados são a matéria-prima do ML.

---

### 🔎 EDA — Análise exploratória de dados

<p align="justify">EDA (Exploratory Data Analysis) consiste em explorar os dados para entender sua estrutura, qualidade, distribuição e possíveis problemas.</p>

Pode envolver:

- identificar valores ausentes;
- detectar outliers;
- analisar distribuições;
- encontrar correlações;
- verificar desequilíbrio entre classes;
- entender os atributos disponíveis.

> **PEGADINHA:** EDA não é treinamento. É entender os dados antes de treinar.

---

### 🧹 Pré-processamento

<p align="justify">Consiste em preparar os dados para que possam ser utilizados pelo modelo.</p>

Exemplos:

- tratar valores ausentes;
- remover dados inválidos;
- normalizar valores;
- codificar categorias;
- limpar textos;
- converter formatos.

> **DECORA:** pré-processamento = **preparar os dados**.

---

### 🧬 Feature Engineering

<p align="justify">É a criação, transformação ou seleção de atributos (<strong>features</strong>) relevantes para o modelo.</p>

Exemplo:

<pre>
Data da compra
      ↓
Dia da semana
      ↓
Final de semana? → SIM/NÃO
</pre>

Outro exemplo:

<pre>
Data de nascimento
      ↓
Idade
      ↓
Feature utilizada pelo modelo
</pre>

> **DECORA:** Feature Engineering = transformar dados em atributos úteis para o modelo.

---

### 🧠 Treinamento

<p align="justify">Durante o treinamento, o algoritmo aprende padrões a partir dos dados de treinamento.</p>

<pre>
Dados de treinamento
        ↓
     Algoritmo
        ↓
       Modelo
</pre>

> **DECORA:** treinamento = **aprender**.

---

### ⚙️ Ajuste de hiperparâmetros

<p align="justify">Hiperparâmetros são configurações utilizadas para controlar o processo de treinamento. O ajuste busca encontrar configurações que produzam melhor desempenho.</p>

Exemplos:

- taxa de aprendizado;
- profundidade de árvore;
- número de árvores;
- tamanho de lote.

> **PEGADINHA:** hiperparâmetro não é a mesma coisa que parâmetro aprendido pelo modelo durante o treinamento.

---

### 📊 Avaliação

<p align="justify">Após o treinamento, o modelo é avaliado para verificar seu desempenho em dados apropriados.</p>

Algumas métricas:

- Accuracy;
- Precision;
- Recall;
- F1;
- AUC.

> **DECORA:** treinamento = aprender; avaliação = verificar se aprendeu bem.

---

### 🚀 Deployment

<p align="justify">Deployment é a implantação do modelo para que ele possa ser utilizado por aplicações, sistemas ou usuários.</p>

<pre>
Aplicação
   ↓
  API
   ↓
Modelo
   ↓
Predição
</pre>

Pode ser realizado por:

- API gerenciada;
- API auto-hospedada.

---

### 👀 Monitoramento

<p align="justify">Depois que o modelo entra em produção, é necessário acompanhar seu comportamento.</p>

Pode-se monitorar:

- desempenho;
- latência;
- erros;
- qualidade das previsões;
- mudanças nos dados;
- custos;
- métricas do negócio.

> 🔥 **DECORA:** modelo em produção não deve ser simplesmente abandonado.

---

<h3><strong style='color: skyblue'>2️⃣ Pipeline completo — saiba diferenciar</strong></h3>

| Etapa | O que acontece? |
|---|---|
| Coleta | Obtém os dados |
| EDA | Entende os dados |
| Pré-processamento | Limpa/prepara os dados |
| Feature Engineering | Cria/transforma atributos |
| Treinamento | Modelo aprende |
| Hyperparameter Tuning | Ajusta configurações |
| Avaliação | Mede desempenho |
| Deployment | Coloca em produção |
| Monitoramento | Acompanha o modelo |
| Retreinamento | Atualiza o modelo |

> 🔥 **PEGADINHA:** a prova pode descrever uma situação e perguntar em qual etapa ela acontece.

<h3><strong style='color: skyblue'>3️⃣ Origem dos modelos de ML</strong></h3>

<p align="justify">Um modelo pode ser obtido de diferentes formas. O exame destaca principalmente modelos pré-treinados, modelos de código aberto e modelos personalizados.</p>

### 🟢 Modelo pré-treinado

<p align="justify">É um modelo que já passou por treinamento e pode ser utilizado diretamente ou adaptado para uma tarefa.</p>

<pre>
Modelo pré-treinado
        ↓
   Adaptar / usar
        ↓
    Aplicação
</pre>

Vantagens:

- desenvolvimento mais rápido;
- menor necessidade de treinamento do zero;
- redução de tempo;
- pode reduzir custos.

> **DECORA:** pré-treinado = **já foi treinado**.

---

### 🟡 Modelo de código aberto

<p align="justify">Modelo disponibilizado publicamente sob uma determinada licença, permitindo seu uso ou modificação conforme os termos dessa licença.</p>

É necessário considerar:

- licença;
- custos;
- infraestrutura;
- segurança;
- capacidade de customização;
- requisitos operacionais.

> **PEGADINHA:** código aberto não significa automaticamente gratuito ou sem restrições.

---

### 🔴 Modelo personalizado

<p align="justify">Modelo criado, treinado ou adaptado para atender a uma necessidade específica.</p>

<pre>
Dados específicos
       ↓
Treinamento / adaptação
       ↓
Modelo personalizado
       ↓
Caso de uso específico
</pre>

Pode fazer sentido quando:

- o problema é muito específico;
- os dados próprios são importantes;
- é necessário maior controle;
- modelos existentes não atendem adequadamente.

> 🔥 **DECORA:**  
> Pré-treinado → rapidez para começar.  
> Personalizado → maior adaptação ao caso específico.

---

<h3><strong style='color: skyblue'>4️⃣ Métodos para usar um modelo em produção</strong></h3>

### ☁️ API gerenciada

<p align="justify">O provedor gerencia grande parte da infraestrutura necessária para disponibilizar o modelo.</p>

<pre>
Aplicação
   ↓
API gerenciada
   ↓
Modelo
</pre>

Vantagens:

- menor carga operacional;
- infraestrutura gerenciada;
- escalabilidade mais simples;
- desenvolvimento mais rápido.

> **DECORA:** API gerenciada = **menos infraestrutura para administrar**.

---

### 🖥️ API auto-hospedada

<p align="justify">A organização gerencia a infraestrutura necessária para hospedar e disponibilizar o modelo.</p>

<pre>
Aplicação
   ↓
API da organização
   ↓
Infraestrutura
   ↓
Modelo
</pre>

Pode exigir gerenciamento de:

- servidores;
- containers;
- escalabilidade;
- atualizações;
- disponibilidade;
- segurança;
- custos;
- modelo.

> **DECORA:** self-hosted = **mais controle + mais responsabilidade**.

---

### ⚖️ API gerenciada × API auto-hospedada

| Característica | API gerenciada | API auto-hospedada |
|---|---|---|
| Infraestrutura | Provedor gerencia | Organização gerencia |
| Controle | Menor | Maior |
| Operação | Mais simples | Mais complexa |
| Escalabilidade | Geralmente mais simples | Responsabilidade da organização |
| Carga operacional | Menor | Maior |

> **PEGADINHA:** auto-hospedada não significa necessariamente servidor físico próprio. Pode ser infraestrutura em nuvem administrada pela organização.

<h3><strong style='color: skyblue'>6️⃣ MLOps</strong></h3>

<p align="justify"><strong>MLOps (Machine Learning Operations)</strong> é o conjunto de práticas para desenvolver, implantar e operar modelos de ML de forma confiável, repetível, escalável e sustentável.</p>

<pre>
Desenvolver
    ↓
Experimentar
    ↓
Validar
    ↓
Produzir
    ↓
Monitorar
    ↓
Atualizar
    ↺
</pre>

O exame destaca:

- experimentação;
- processos repetíveis;
- sistemas escaláveis;
- gerenciamento de dívida técnica;
- prontidão para produção;
- monitoramento;
- retreinamento.

---

### 🧪 Experimentação

<p align="justify">Testar diferentes modelos, dados, algoritmos e configurações para encontrar uma solução adequada.</p>

> **DECORA:** MLOps deve tornar experimentos rastreáveis e reproduzíveis.

---

### 🔁 Processos repetíveis

<p align="justify">O processo de treinamento, avaliação e deployment deve poder ser executado novamente de maneira consistente.</p>

<pre>
Código + Dados + Configuração
             ↓
       Mesmo processo
             ↓
       Resultado reproduzível
</pre>

Automação ajuda a reduzir inconsistências manuais.

---

### 📈 Sistemas escaláveis

<p align="justify">A solução deve conseguir lidar com o crescimento de dados, usuários e requisições.</p>

<pre>
100 usuários
     ↓
1.000 usuários
     ↓
100.000 usuários
</pre>

> **DECORA:** escalabilidade = capacidade de crescer sem precisar reconstruir toda a solução.

---

### 🧾 Dívida técnica

<p align="justify">Dívida técnica ocorre quando atalhos ou decisões tomadas hoje geram trabalho adicional, manutenção ou problemas no futuro.</p>

Exemplos:

- código difícil de manter;
- processos manuais;
- falta de testes;
- pipelines não automatizados;
- documentação insuficiente;
- falta de rastreabilidade.

> **DECORA:** dívida técnica = **problema futuro causado por decisões atuais**.

---

### 🚀 Prontidão para produção

Antes do deployment, considerar:

- desempenho;
- segurança;
- confiabilidade;
- escalabilidade;
- custo;
- monitoramento;
- integração;
- operação;
- requisitos do negócio.

> **PEGADINHA:** boa métrica de teste ≠ automaticamente pronto para produção.

---

### 👀 Monitoramento de modelos

<p align="justify">Depois do deployment, o modelo precisa ser acompanhado para identificar degradação de desempenho, mudanças nos dados e problemas operacionais.</p>

<pre>
Modelo em produção
       ↓
   Monitoramento
       ↓
Problema detectado?
    ↙         ↘
  NÃO         SIM
   ↓           ↓
Continuar   Investigar
               ↓
          Retreinar?
</pre>

---

### 🔄 Retreinamento

<p align="justify">Quando os dados ou o comportamento do problema mudam, o modelo pode precisar ser atualizado ou treinado novamente.</p>

<pre>
Dados antigos
     ↓
Modelo
     ↓
Produção
     ↓
Dados mudam
     ↓
Desempenho pode cair
     ↓
Retreinamento
     ↓
Novo modelo
</pre>

> **DECORA:** modelo de ML pode degradar com o tempo porque os dados e o comportamento do mundo real mudam.

---

<h3><strong style='color: skyblue'>7️⃣ Métricas de desempenho do modelo</strong></h3>

<p align="justify">As métricas de desempenho avaliam quão bem o modelo está realizando sua tarefa.</p>

## 🎯 Accuracy — Acurácia

<p align="justify">Percentual de previsões corretas em relação ao total de previsões.</p>

<pre>
Accuracy =
previsões corretas
──────────────────
total de previsões
</pre>

Exemplo:

<pre>
100 previsões
90 corretas

Accuracy = 90%
</pre>

> **DECORA:** Accuracy = **"quantas previsões no total eu acertei?"**

### ⚠️ Pegadinha

Accuracy pode ser enganosa quando as classes estão muito desequilibradas.

Exemplo:

<pre>
1000 transações
990 normais
10 fraudulentas
</pre>

Se o modelo classificar tudo como normal:

<pre>
990 acertos / 1000 = 99% Accuracy
</pre>

Mas ele não detectou nenhuma fraude.

---

## 🎯 Precision — Precisão

<p align="justify">Entre todas as previsões positivas feitas pelo modelo, quantas realmente eram positivas.</p>

<pre>
Precision =
TP
──────────
TP + FP
</pre>

Pergunta mental:

> **"Quando o modelo disse POSITIVO, quantas vezes ele estava certo?"**

Exemplo:

<pre>
Modelo marcou 100 transações como fraude
80 eram realmente fraude

Precision = 80%
</pre>

> **DECORA:** Precision olha para os **positivos previstos**.

---

## 🔎 Recall — Revocação / Sensibilidade

<p align="justify">Entre todos os positivos que realmente existem, quantos o modelo conseguiu identificar.</p>

<pre>
Recall =
TP
──────────
TP + FN
</pre>

Pergunta mental:

> **"De todos os positivos que realmente existiam, quantos eu encontrei?"**

Exemplo:

<pre>
Existiam 100 fraudes
modelo encontrou 90

Recall = 90%
</pre>

> **DECORA:** Recall olha para os **positivos reais**.

---

## ⚖️ F1 Score

<p align="justify">É a média harmônica entre Precision e Recall.</p>

<pre>
F1 =
2 × Precision × Recall
──────────────────────
Precision + Recall
</pre>

> **DECORA:** F1 = **equilíbrio entre Precision e Recall**.

---

### 🧠 Tabela definitiva

| Métrica | Pergunta mental |
|---|---|
| **Accuracy** | Quantos acertos tive no total? |
| **Precision** | Dos positivos que previ, quantos estavam certos? |
| **Recall** | Dos positivos que realmente existiam, quantos encontrei? |
| **F1** | Como equilibrar Precision e Recall? |

<pre>
                 CLASSIFICAÇÃO

Accuracy  → acertos / total

Precision → positivos previstos
            "Quando digo POSITIVO, estou certo?"

Recall    → positivos reais
            "Encontrei os POSITIVOS que existiam?"

F1        → equilíbrio
            "Como combinar Precision + Recall?"
</pre>

<h3><strong style='color: skyblue'>8️⃣ Métricas de negócio</strong></h3>

<p align="justify">Um modelo pode apresentar boas métricas técnicas e ainda assim não gerar valor para a empresa. Por isso, também são avaliadas métricas de negócio.</p>

### 💰 Custo por usuário

Quanto custa atender cada usuário utilizando a solução.

<pre>
Custo total
───────────
nº usuários
</pre>

---

### 💵 Custos de desenvolvimento

Quanto foi gasto para construir e colocar a solução em funcionamento.

Pode envolver:

- desenvolvimento;
- infraestrutura;
- dados;
- treinamento;
- integração;
- operação.

---

### 💬 Feedback dos clientes

Avalia a percepção dos usuários sobre a solução.

Exemplos:

- satisfação;
- reclamações;
- avaliações;
- aceitação;
- taxa de uso.

---

### 📈 ROI — Return on Investment

Avalia o retorno obtido em relação ao investimento realizado.

Conceitualmente:

<pre>
ROI =
retorno obtido
──────────────
investimento
</pre>

> **DECORA:** métrica técnica responde **"o modelo funciona?"**; métrica de negócio responde **"isso gera valor?"**.

---

<h3><strong style='color: skyblue'>9️⃣ Modelo bom ≠ negócio bom</strong></h3>

Imagine:

<pre>
Modelo
Accuracy = 95%
</pre>

Mas:

<pre>
Custo por usuário = alto
Infraestrutura = cara
Latência = alta
Clientes = insatisfeitos
ROI = baixo
</pre>

<p align="justify">O modelo pode apresentar boa performance técnica e ainda assim não gerar o resultado empresarial esperado.</p>

> 🔥 **PROVA:** não confunda **performance do modelo** com **sucesso do negócio**.

<h3><strong style='color: skyblue'>🔥 DECORAÇÃO FINAL — O que realmente memorizar</strong></h3>

> **1. Pipeline:** Dados → EDA → Pré-processamento → Features → Treinamento → Tuning → Avaliação → Deployment → Monitoramento.

> **2. Treinamento:** modelo aprende.

> **3. Avaliação:** verifica desempenho.

> **4. Deployment:** coloca o modelo em produção.

> **5. Monitoramento:** acompanha o modelo em produção.

> **6. Retreinamento:** atualiza o modelo quando necessário.

> **7. SageMaker AI:** pense em ciclo de vida de ML.

> **8. Bedrock:** pense em Foundation Models e GenAI.

> **9. Managed API:** menos infraestrutura para administrar.

> **10. Self-hosted:** mais controle, mais responsabilidade operacional.

> **11. Accuracy:** acertos totais.

> **12. Precision:** "dos positivos que previ, quantos estavam certos?"

> **13. Recall:** "dos positivos reais, quantos encontrei?"

> **14. F1:** equilíbrio entre Precision e Recall.

> **15. Métrica técnica:** "o modelo funciona?"

> **16. Métrica de negócio:** "o modelo gera valor?"

---

<h3><strong style='color: skyblue'>⚠️ PEGADINHAS DE PROVA</strong></h3>

- **EDA ≠ treinamento.**
- **Pré-processamento ≠ Feature Engineering.**
- **Treinamento ≠ avaliação.**
- **Modelo treinado ≠ modelo pronto para produção.**
- **Deployment ≠ monitoramento.**
- **API gerenciada ≠ API auto-hospedada.**
- **Código aberto ≠ necessariamente gratuito.**
- **Accuracy alta ≠ necessariamente bom modelo**, principalmente com classes desbalanceadas.
- **Precision ≠ Recall.**
- **Boa métrica de ML ≠ necessariamente bom resultado empresarial.**
- **MLOps não é apenas deployment:** envolve experimentação, repetibilidade, escalabilidade, dívida técnica, prontidão para produção, monitoramento e retreinamento.
